# Media Pipeline Architecture

## Rule
Every image that enters or leaves PostLap AI — whether uploaded by users or generated by AI — must go through MediaService and be served via `/uploads/…` public URLs. No feature may write files or return image data (Base64, data: URIs) outside this gateway.

**Why:** Before this was enforced, ads.ts returned generated images as large data: URIs (lost on refresh), and only recognised logo/design-sample assets stored as data: URIs (ignoring the newer /uploads/ paths). This caused broken images after page refresh and inconsistency across features.

**How to apply:**
- Upload → `MediaService.saveFile(companyId, category, name, buffer, mimeType)` → returns `{ publicUrl }`
- Store `publicUrl` (starts with `/uploads/`) in the DB
- Serve statically: `app.use("/uploads", express.static(storageRoot))` where `storageRoot = path.resolve(__dirname, "../storage")`
- In dev, Vite proxy forwards `/uploads` to the API server via `API_TARGET` env var (set in artifact.toml to `http://127.0.0.1:5000`)
- Generated images (`/image-gen` endpoint) are saved via `saveGeneratedImage()` helper and returned as `/uploads/` URLs with data: fallback on storage failure

## __dirname in compiled bundle
Both `app.ts` and `MediaService.ts` use `__dirname`. The esbuild banner injects:
```
globalThis.__dirname = path.dirname(fileURLToPath(import.meta.url))
```
So `__dirname` = `dist/` in the compiled bundle, making `path.resolve(__dirname, "../storage")` resolve to `artifacts/api-server/storage/` — the correct location.

## Static serving details
- Mount: `app.use("/uploads", express.static(storageRoot))`
- Security headers on uploads: `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'`  
- These headers do NOT prevent `<img>` tags from rendering images (CSP applies to documents, not binary image responses)
- Express.static sets correct MIME types automatically (image/png, image/jpeg, etc.)

## ads.ts — reading assets for Gemini context
`uploadsUrlToBase64(publicUrl)` converts `/uploads/…` paths to base64 for inline Gemini data. Containment check guards against path traversal. Both legacy `data:` URIs and new `/uploads/` paths are supported for backward compatibility.
