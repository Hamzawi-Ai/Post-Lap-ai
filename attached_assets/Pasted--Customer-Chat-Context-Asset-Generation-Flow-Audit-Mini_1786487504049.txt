# Customer Chat — Context, Asset & Generation Flow Audit + Minimal Production Fixes

## OBJECTIVE

We have already fixed Task #72 and confirmed that Customer Chat multi-turn conversations now work.

The current production/preview test exposed a SECOND layer of problems.

The goal of this task is NOT to redesign Customer Chat, rewrite the persona, migrate AI providers, or rebuild the prompt architecture.

The goal is:

1. Find why the Customer Chat context is not being used reliably.
2. Find why saved brand assets / conversation images are apparently not reaching the AI/image-generation flow as actual usable inputs.
3. Find why the real ad-policy check result is not reliably driving the chat response.
4. Find why the assistant sometimes starts image generation before the user explicitly asks it to generate.
5. Fix only confirmed causes with the smallest safe production changes.
6. Verify the real user flows in Preview.

This is a narrow production-readiness task.

Observed behavior:

The user previously uploaded/referenced an image in the same conversation.

Later they asked to modify/use that design.

The assistant responded as if it remembered the image, but the generated result was substantially different.

We need to verify whether the model actually receives the previous image.

Trace:

uploaded image
→ message/attachment record
→ conversation history
→ context reconstruction
→ model message payload
→ image-generation request

Important:

Conversation history text is NOT equivalent to multimodal image access.

If the previous image is only represented by:
- a filename
- a description
- metadata
- a URL that is not actually passed to the model
- or a textual reference

then report that clearly and fix the smallest possible missing handoff.

Acceptance:

If the user says:

"عدّل التصميم السابق"

the generation flow must have access to the previous generated/reference image when the product architecture says that image should be reusable.

Do not redesign the whole asset system.

# 4. POLICY CHECK RESULT IS NOT RELIABLY DRIVING CHAT

Observed behavior:

When the user uploads an advertising image, the application performs a check.

The first automatic result can be generic/weak.

After the user explicitly asks the assistant to check it again, the answer can become more specific.

We need to inspect the existing real flow.

Known architecture:

/api/check produces the advertising/policy report.

The current implementation injects reportSummary into the user message in routes/hamzawi.ts.

Inspect exactly how:

/api/check
→ reportSummary
→ POST /hamzawi/chat
→ user message
→ model context

Determine:

1. Is the complete reportSummary reaching Customer Chat?
2. Is the report associated with the correct uploaded image?
3. Is the report lost when the conversation continues?
4. Is the assistant receiving only a summary instead of the actual report?
5. Is the model being instructed to treat the actual check result as authoritative?
6. Is there any path where the user asks for a second check and the system performs a new analysis instead of using the original result?

Do NOT invent a new policy-analysis system.

The existing check endpoint is the source of truth.

If the real report is already available, make Customer Chat use that report correctly.

If the report is NOT actually reaching the chat context, fix that handoff.

Acceptance:

Upload a known policy-problematic advertising image.

The assistant should respond based on the actual check result, not generic marketing-policy advice.

Do not claim that an image is compliant/non-compliant unless the actual check result supports it.

# 5. ASSISTANT GENERATES A DESIGN WITHOUT EXPLICIT USER REQUEST

Observed behavior:

User asked:

"شو بتقترح؟"

The assistant immediately started designing.

This is incorrect.

The existing product behavior should distinguish between:

- asking for advice
- asking for ideas
- asking what is recommended
- asking for clarification
- explicitly requesting generation
- explicitly requesting modification

Image generation should NOT automatically start merely because the conversation is about design.

Inspect:

- getDesignGenerationInstruction(...)
- composeSystemPrompt(...)
- tool/generation decision logic
- any intent detection
- image-generation trigger conditions

The expected behavior is:

User:
"شو بتقترح؟"

Assistant:
provides options/recommendations and waits.

User:
"تمام صمم الخيار الثاني"

Assistant:
generates.

Likewise:

"اعمل لي تصميم..."
"صمم..."
"نفذ هذا التصميم..."
"عدل التصميم السابق..."

are explicit generation/edit requests.

Do not create an oversized new intent system.

Fix the existing generation gate at the smallest appropriate layer.

Acceptance:
- "شو بتقترح؟" → NO generation
- "شو بتنصحني؟" → NO generation
- "كيف ممكن نصممها؟" → NO generation
- "صممها" → generation allowed
- "نفذ الخيار الثاني" → generation allowed
- "عدل التصميم السابق" → generation/edit allowed
