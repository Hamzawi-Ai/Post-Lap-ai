POSTLAB — PRODUCTION CHAT CONTINUITY & ROUTING FIX
==================================================

Goal
----

PostLab is now published and the immediate goal is simple:

MAKE THE CUSTOMER CHAT RELIABLY WORK FOR REAL USERS.

The current Production app successfully opens the Customer Chat and can produce an initial response, but during real usage we observed that the conversation often fails after the first exchange.

I want you to investigate the actual cause, verify the complete Customer Chat flow, and make only the necessary, low-risk fixes required to get the current chat experience working reliably.

This is a focused production bug-fix task, NOT a redesign or refactor.


CURRENT OBSERVED BEHAVIOR
-------------------------

Production testing showed:

1. A new conversation can receive an initial assistant response.

2. Subsequent messages in the same conversation may fail and return the generic error:
   "عذرًا، حدث خطأ. حاول مرة أخرى."

3. The failure appears to affect multi-turn conversation continuity.

4. The assistant persona "Nader" (نادر) was recently introduced as an internal creative persona through the Customer Chat prompt system.
   Nader is intentionally a prompt/persona concept, NOT a separate technical agent, service, route, or architecture.

5. When the user explicitly tried to invoke Nader, the request did not receive the expected response and instead fell into the error/fallback behavior.

6. We also observed that some conversations appear to work on the first message and then fail on later messages.

7. The FREE / PRO two-tier UI is currently visible and appears to be functioning.
   Do NOT modify the subscription architecture as part of this task unless you prove that it is directly responsible for the current Chat failure.

Nader is intentionally a creative persona defined through the PostLab Customer Chat prompt system.

Do NOT create:

- a new Nader agent
- a new API route
- a new service
- a separate model
- a separate architecture

Instead verify that a request involving Nader correctly passes through the existing Customer Chat prompt/response flow.

The expected behavior is:

User asks for Nader
→ existing Customer Chat recognizes the creative persona request
→ appropriate existing prompt/persona instructions are included
